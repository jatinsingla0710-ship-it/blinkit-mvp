RichlyBook 2.0 — Core Sales UX Audit

Phase 1: New Sale + Customer + Product
Audit only — no code, schema, or migrations changed
Date: 7 October 2026  ·  Vyapar used as UX/workflow benchmark only (not a UI copy)

Verdict RichlyBook is a wholesale assisted-order ERP (order → approve/reserve → pack → deliver → full pay → convert), not a Vyapar-style one-screen retail counter sale. Dashboard “New Sale” opens a minimal assisted-order modal. Most backend pieces for catalogue sales, payments, invoices, stock, and books exist — but owner New Sale UX is the wrong product shape for a shop counter.

9. UX Problems

  1. “New Sale” ≠ sale — opens assisted wholesale order.
  2. Orders page has no primary create CTA.
  3. Too many steps to finish money.
  4. Admin create is one SKU; salesman app is better.
  5. Price fields look editable but do not stick.
  6. Payment method not choosable despite copy.
  7. Terminology (Assisted Order, Stock Reserved, Convert) is ops-console language.
  8. Customer/product create forms are heavy for counter use.
  9. Overall feel is internal admin dashboard, not Indian shop accounting software.

13. Duplicate / Conflicting Implementations

  1. Create order: Admin 1-line modal vs Sales PWA cart vs post-create replace-lines.
  2. Invoice: Pre-sale admin_create_order_invoice vs sale invoice on convert.
  3. Payment: Order mark-paid vs payment proof scan vs delivery COD collect.
  4. Bill photo OCR: Supplier purchases only — not customers.
  5. Labels: Nav “Sales” → Orders; Quick action “New Sale” → Assisted Order.

14. Recommended Reuse

Do not rebuild or fork:

  • place_assisted_order / preview_assisted_order_lines / replace-lines RPCs
  • admin_mark_payment_received, admin_convert_order_to_sale, cancel/refund
  • OrderInvoicePrint + company settings
  • Inventory reserve/consume + movements
  • admin_sync_accounting_journals + day book
  • Customer ledger / receivables / dues
  • Product / SKU / pricing / inventory stack
  • Sales PWA cart patterns as UX reference for Admin New Sale

15. Recommended Changes (design only)

  1. Owner New Sale screen that completes money in one flow (reuse RPCs or thin wrappers).
  2. Walk-in + quick customer create.
  3. Multi-line cart + custom items (schema/RPC decision required).
  4. If price override is a product need, change server contract — UI alone is insufficient.
  5. Payment: method + amount paid + due (extend mark-paid).
  6. Immediate bill print/share after complete; GST on bill when rates present.
  7. Keep wholesale long lifecycle for B2B; layer counter-sale path; do not delete.

Recommended First Implementation

  1. Owner New Sale shell (Admin) — multi-line cart using preview/place + Sales PWA patterns; primary CTA on Sales/Orders.
  2. Customer select + quick-create + Walk-in (minimal fields).
  3. Catalogue lines + Custom item (backend must allow non-SKU or ephemeral SKU — decide before UI).
  4. Payment panel — Cash/UPI/Bank/Credit + amount paid / due.
  5. Complete → invoice print (shorten counter path; keep wholesale lifecycle).
  6. Confirm stock + outstanding + journal sync still fire from existing RPCs.
